# AtlasX Deployment Guide

## Overview

This guide covers deploying AtlasX to production using Kubernetes. AtlasX is now enterprise-ready with comprehensive infrastructure, security, and services to compete with platforms like Revolut and Wise.

---

## Prerequisites

### Required Tools
- `kubectl` (v1.27+)
- `helm` (v3.12+)
- `docker` (v24.0+)
- `terraform` (v1.5+)
- `gcloud` CLI (for GCP) or `aws` CLI (for AWS)

### Access Requirements
- Kubernetes cluster admin access
- Container registry credentials
- DNS management access
- SSL certificate authority access

## Infrastructure Setup

### 1. Provision Infrastructure with Terraform

```bash
cd infra/terraform

# Initialize Terraform
terraform init

# Review the plan
terraform plan \
  -var="project_id=your-gcp-project" \
  -var="region=us-east1" \
  -var="environment=production"

# Apply infrastructure
terraform apply \
  -var="project_id=your-gcp-project" \
  -var="region=us-east1" \
  -var="environment=production"

# Save outputs
terraform output > terraform-outputs.txt
```

This creates:
- GKE cluster with auto-scaling (3-10 nodes)
- Cloud SQL PostgreSQL (regional HA)
- Cloud Memorystore Redis (HA)
- VPC with private networking
- Service accounts with minimal permissions

### 2. Configure kubectl

```bash
# GCP
gcloud container clusters get-credentials atlasx-production --region us-east1

# Verify connection
kubectl cluster-info
kubectl get nodes
```

## Application Deployment

### Method 1: Using Helm (Recommended)

```bash
cd infra/helm/atlasx

# Add required Helm repositories
helm repo add bitnami https://charts.bitnami.com/bitnami
helm repo update

# Create namespace
kubectl create namespace atlasx

# Create secrets
kubectl create secret generic atlasx-secrets \
  --from-literal=DATABASE_PASSWORD=<your-db-password> \
  --from-literal=REDIS_PASSWORD=<your-redis-password> \
  --from-literal=JWT_SECRET=<your-jwt-secret> \
  --from-literal=JWT_REFRESH_SECRET=<your-jwt-refresh-secret> \
  --from-literal=ENCRYPTION_KEY=<32-byte-hex-key> \
  --from-literal=ONFIDO_API_TOKEN=<your-onfido-token> \
  --from-literal=SUMSUB_API_KEY=<your-sumsub-key> \
  --from-literal=MARQETA_API_KEY=<your-marqeta-key> \
  -n atlasx

# Deploy with Helm
helm install atlasx . \
  --namespace atlasx \
  --set image.tag=$(git rev-parse --short HEAD) \
  --set global.environment=production \
  --values values-production.yaml \
  --wait \
  --timeout 10m

# Check deployment status
helm status atlasx -n atlasx
kubectl get pods -n atlasx -w
```

### Method 2: Using kubectl

```bash
cd infra/k8s

# Create namespace
kubectl apply -f base/namespace.yaml

# Create configs and secrets
kubectl apply -f base/configmap.yaml
kubectl apply -f base/secrets.yaml

# Deploy databases
kubectl apply -f base/postgres-statefulset.yaml
kubectl apply -f base/redis-statefulset.yaml

# Wait for databases to be ready
kubectl wait --for=condition=ready pod -l app=postgres -n atlasx --timeout=300s
kubectl wait --for=condition=ready pod -l app=redis -n atlasx --timeout=300s

# Deploy application
kubectl apply -f base/api-deployment.yaml
kubectl apply -f base/ingress.yaml

# Deploy monitoring
kubectl apply -f monitoring/prometheus-deployment.yaml
kubectl apply -f monitoring/grafana-deployment.yaml
kubectl apply -f monitoring/loki-deployment.yaml

# Apply network policies
kubectl apply -f base/network-policy.yaml

# Check all pods
kubectl get pods -n atlasx
```

## SSL/TLS Configuration

### Using cert-manager (Automated)

```bash
# Install cert-manager
kubectl apply -f https://github.com/cert-manager/cert-manager/releases/download/v1.13.0/cert-manager.yaml

# Create Let's Encrypt issuer
cat <<EOF | kubectl apply -f -
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: letsencrypt-prod
spec:
  acme:
    server: https://acme-v02.api.letsencrypt.org/directory
    email: devops@atlasx.io
    privateKeySecretRef:
      name: letsencrypt-prod
    solvers:
    - http01:
        ingress:
          class: nginx
EOF

# Certificate will be auto-generated by Ingress annotation
```

## Scaling

### Manual Scaling

```bash
# Scale API pods
kubectl scale deployment atlasx-api --replicas=10 -n atlasx

# Scale database
kubectl scale statefulset postgres --replicas=3 -n atlasx
```

### Auto-scaling

Horizontal Pod Autoscaler is pre-configured:
- Min replicas: 3
- Max replicas: 20
- Target CPU: 70%
- Target Memory: 80%

```bash
# Check HPA status
kubectl get hpa -n atlasx

# Adjust HPA
kubectl patch hpa atlasx-api-hpa -n atlasx -p '{"spec":{"maxReplicas":50}}'
```

## Backup & Recovery

### Database Backups

```bash
# Manual backup
kubectl exec -it postgres-0 -n atlasx -- \
  pg_dump -U postgres atlasx | gzip > backup-$(date +%Y%m%d).sql.gz

# Restore from backup
gunzip < backup-20250115.sql.gz | \
  kubectl exec -i postgres-0 -n atlasx -- \
  psql -U postgres atlasx
```

### Automated Backups (Cloud SQL)

Cloud SQL automatically creates backups:
- Daily backups at 02:00 UTC
- 30-day retention
- Point-in-time recovery enabled

## Security Hardening

### 1. Network Policies

Network policies are enforced by default:
- API pods can only access PostgreSQL and Redis
- PostgreSQL/Redis only accessible from API pods
- External HTTPS traffic only via Ingress

### 2. Secrets Management

**Production Best Practice:** Use external secrets manager

```bash
# Install External Secrets Operator
helm repo add external-secrets https://charts.external-secrets.io
helm install external-secrets external-secrets/external-secrets -n external-secrets-system --create-namespace

# Configure GCP Secret Manager backend
kubectl apply -f - <<EOF
apiVersion: external-secrets.io/v1beta1
kind: SecretStore
metadata:
  name: gcpsm-secret-store
  namespace: atlasx
spec:
  provider:
    gcpsm:
      projectID: "your-project-id"
      auth:
        workloadIdentity:
          clusterLocation: us-east1
          clusterName: atlasx-production
          serviceAccountRef:
            name: external-secrets-sa
EOF
```

### 3. Pod Security

```bash
# Apply Pod Security Standards
kubectl label namespace atlasx pod-security.kubernetes.io/enforce=restricted
```

## Rollback Procedures

### Using Helm

```bash
# View release history
helm history atlasx -n atlasx

# Rollback to previous version
helm rollback atlasx -n atlasx

# Rollback to specific revision
helm rollback atlasx 3 -n atlasx
```

### Using kubectl

```bash
# View deployment history
kubectl rollout history deployment/atlasx-api -n atlasx

# Rollback to previous version
kubectl rollout undo deployment/atlasx-api -n atlasx

kubectl rollout undo deployment/atlasx-api --to-revision=2 -n atlasx
```

## Troubleshooting

### Pods Not Starting

```bash
# Check pod status
kubectl get pods -n atlasx

# Describe pod
kubectl describe pod <pod-name> -n atlasx

# View logs
kubectl logs <pod-name> -n atlasx --tail=100

# Check events
kubectl get events -n atlasx --sort-by='.lastTimestamp'
```

### Database Connection Issues

```bash
# Test PostgreSQL connection
kubectl exec -it postgres-0 -n atlasx -- psql -U postgres -c "SELECT 1"

# Test Redis connection
kubectl exec -it redis-0 -n atlasx -- redis-cli -a <password> ping
```

### High Memory Usage

```bash
# Check resource usage
kubectl top pods -n atlasx
kubectl top nodes

# Increase memory limits
kubectl patch deployment atlasx-api -n atlasx -p \
  '{"spec":{"template":{"spec":{"containers":[{"name":"atlasx-api","resources":{"limits":{"memory":"2Gi"}}}]}}}}'
```
